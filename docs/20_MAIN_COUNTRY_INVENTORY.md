# 메인 창고 및 국가별 실물 재고

## 확정한 운영 흐름

생산 완료 후 베트남 메인 창고 입고 → 국가 창고로 출고 → 운송 중 → 도착 국가 입고 확인 → 해당 국가 판매.
MAIN과 운송 중 수량은 판매 불가. 베트남 판매분도 MAIN에서 VN으로 출고 및 입고 처리한다. 동일 장소라도 메인 보관분과 판매분을 구분한다.
기존 판매 가능 재고는 MAIN으로 이관한다. 기존 주문 예약과 판매 확정 수량은 VN에 보존하여 취소·반품 시 중복 재고를 만들지 않는다.

## 저장 구조

- inventory/{variantId}: 상품·색상·사이즈별 mainStock, inTransit.KR/VN/HU, countries.KR/VN/HU의 stock/reserved/sold, allocationVersion=1, version.
- 최상위 stock/reserved/sold는 국가별 합계이며 MAIN과 운송 중을 포함하지 않는다. sold는 입금 확인 기준으로, 창고 실물 잔량에 더해서는 안 된다.
- warehouseReceipts: 생산 입고 원전표와 누적 정정 수량.
- warehouseTransfers: 국가 출고 원전표, 출고·부분 입고·손실·반송 수량, 처리 상태.
- inventoryMovements: 변경마다 생성하는 원장. 전후 잔량, 처리자, 서버 처리 시각, SKU, 국가, 처리 수량, 주문/입고/출고 전표 연결과 사유를 보존.
- inventoryRequests: 동일 요청 재시도를 한 번만 처리하기 위한 기록.
- stockAvailability: 공개용 국가별 판매 가능 수량만 제공. 메인과 원장은 관리자 전용.
- orders.inventoryCountry: 주문 생성 당시 배송 국가를 고정. IP 판매 허용 국가(salesCountry)와 구분한다. 기존 국가 필드 없는 주문은 VN 예약으로 복원한다.

## 관리자 사용

상품 관리의 재고 버튼에서 현황, 재고 전표 처리, 국가 출고 전표, 전체 처리 이력을 조회한다. 실시간 구독으로 변경을 반영한다.
한 번에 한 색상·사이즈를 처리한다. 전표번호와 사유는 필수다. 같은 생산번호의 다른 SKU는 각각 입고할 수 있지만 동일 SKU 중복 입고는 차단한다.

1. 기존 SKU는 ‘메인 이관’ 처리. 새 SKU는 바로 ‘생산 완료 입고’ 가능.
2. 국가 출고 시 국가와 수량 입력. MAIN 감소, 운송 중 증가.
3. 현지 입고 담당자가 원출고 전표를 선택하고 실제 도착 수량 입력. 부분 입고 가능.
4. 운송 손실 또는 실제 메인 반송 입고도 같은 원출고 전표에 연결. 남은 운송 수량을 초과할 수 없다.
5. 생산 입고 오류는 원입고를 선택해 정정 차감. 원장 삭제 없이 별도 이력이 생성된다.
6. 이력의 상세 항목에서 전후 잔량과 처리자·연결 전표를 확인. 이전 이력 불러오기로 과거 기록을 계속 조회한다.

생산 입고 정정은 SKU 합계 재고를 기준으로 한다. 생산 로트별 실물 추적 및 FIFO는 구현 범위에 포함하지 않는다. 기존에 기록되지 않은 과거 거래의 상세 이력은 복원하지 않는다.

## 판매 및 감사 기록

주문 예약 시 해당 국가 판매 가능 수량을 예약으로 이동. 입금 확인 시 예약을 판매 확정으로 이동한다. 고객 배송 출고 시 별도 이력을 남기되 이미 예약된 수량을 다시 차감하지 않는다.
미입금 취소·만료는 원래 국가로 예약 해제. 검수 반품은 원래 국가 재고로 복원하거나 폐기 이력을 남긴다. 환불 송금과 재고 복원은 기존 주문 상태 흐름대로 분리한다.
배송정보 변경은 orderEvents에 변경 전후 택배사·송장을 기록한다.
원장은 클라이언트 수정·삭제 불가하며 관리자만 조회한다. 서버 관리자 권한, 트랜잭션, 버전 검사, 요청 중복 방지로 초과 출고와 중복 입고를 방지한다. 기반시설 관리자 권한까지 차단하는 별도 WORM 보관은 아니다.

## 운영 전환 절차

현재 구현은 로컬이며 운영 데이터 이관 또는 배포를 수행하지 않았다.
1. SKU 재고와 진행 중 주문 백업 및 대조.
2. Firestore 규칙/색인 준비, processWarehouse와 주문 생성·변경·만료 관련 함수 및 프런트엔드 함께 배포.
3. SKU별 메인 이관 후 실제 국가 보유 수량에 맞춰 출고·도착 입고 확인. 이관 직후 국가 입고 전에는 판매 불가.
4. 미전환 SKU는 기존 재고 흐름을 유지한다. 전환된 SKU는 기존 절대수량 덮어쓰기를 서버에서 거부한다.
5. 국가별 판매 가능 재고, 진행 주문 취소/반품 및 중복 요청을 운영 확인.

현재 고객 주문 화면은 VN/VND 배송 운영을 유지한다. KR/HU 창고 재고 관리 추가가 곧 해당 국가 결제 개통을 의미하지 않는다. 국가별 체크아웃 개통 시 배송 국가와 재고 조회 국가를 함께 연결해야 한다.

## 검증

수량 계산, 메인 이관, 기존 예약 보존, 부분 입고, 초과 출고/입고 거부, 국가 재고 격리, 중복 요청 및 중복 생산번호, 동시 출고, 입고 정정, 판매 출고·반품 이력을 자동 검증한다.
Firestore 에뮬레이터 기반 보안 규칙 테스트는 에뮬레이터 미실행 환경에서는 건너뛴다. 실제 운영 데이터로 입출고 테스트는 하지 않는다.
