# 국가별 주문 관리 및 글로벌 개편 검토

검토일: 2026-11-15. 브랜드의 비공개 내부 시스템이 아니라 공식 고객 안내를 조사한 결과와 LikeDzy 권고안을 구분한다.

## 현재 구현

- 주문 목록/상세에 구매 당시 IP 국가(`salesCountry`), 배송 국가(`country`)를 별도 표시한다.
- 전체/KR/VN/HU 필터와 접속/배송 기준 선택을 제공한다. 상태 필터와 함께 서버 쿼리에 적용하므로 현재 페이지 50건에만 제한되지 않는다.
- 누락된 과거 IP 국가는 ‘미기록’. 배송지, 통화, 전화번호로 추정하지 않으며 전체 국가 조회에 포함한다.
- 주문 생성 서버는 검증된 국가 증명에서 `salesCountry`를 저장한다. 이 필드 이름을 선택한 판매 시장이라는 의미로 재해석하면 안 된다.
- 기존 IP 기준 상품 노출·구매 제한은 유지한다. 현재 체크아웃은 베트남 배송/VND이며 한국·헝가리 판매 체크만으로 해당 지역 체크아웃이 활성화되지는 않는다.
- 운영 배포 전 `firestore.indexes.json`의 orders 복합 색인 4개를 배포하고 READY 상태를 확인한 다음 프런트엔드를 배포한다. 운영 배포 시 색인을 먼저 적용한다. 과거 데이터 보정은 수행하지 않는다.

## 공식 사례

- [Zara 배송 안내](https://www.zara.com/us/en/help-center/DeliveryMethods): 구매한 시장/지역과 배송지의 시장/지역이 일치해야 한다. 배송 옵션은 주소와 상품 가용성 등에 따라 달라진다.
- [adidas 튀르키예 결제 안내](https://www.adidas.com.tr/en/help/payment/can-my-delivery-address-be-different-from-my-billing-address): 배송지와 청구지를 다르게 입력할 수 있으나 같은 국가 내 주소로 제한한다. 해당 지역 안내이며 모든 국가 정책으로 일반화하지 않는다.
- [Shopify Markets 현지화](https://help.shopify.com/en/manual/markets/getting-started/localization): 전자상거래 플랫폼 참고 사례. IP로 초기 시장을 결정하되 사용자가 국가·언어를 직접 선택하고 선택을 저장한다. VPN·기업망·통신망 등으로 IP 추정이 부정확할 수 있음을 명시한다.

## LikeDzy 권고 모델 (아직 미구현)

| 주문 기록 | 의미 | 용도 |
| --- | --- | --- |
| accessCountry | 주문 당시 IP 국가 | 유입·이상 주문 분석 |
| marketCode | 고객이 선택한 판매 시장 | 상품/가격/결제 정책과 매출 분류 |
| shippingCountry | 배송 국가 | 배송 가능 여부·배송비·반품 정책 |
| language | 화면 언어 | 고객 안내 및 커뮤니케이션 |
| currency | 실제 주문 통화 | 결제·환불·통계 |

예: 한국에서 접속하고 베트남 배송을 선택하며 영어로 주문하면 KR / VN / VN / en / VND를 각각 기록한다. 국적을 의미하지 않는다.

한 코드베이스와 관리자 화면을 유지하면서 시장별 설정을 둔다. IP는 첫 방문 추천값으로 사용하고 고객이 배송 국가와 언어를 독립적으로 선택하도록 하는 방식을 권고한다. 기존 IP 차단 정책 변경은 별도 결정 후 적용한다.

시장 설정에는 활성화 여부, 허용 배송 국가, 통화, 판매 가격, 배송비, 결제 수단, 반품 안내, 판매 주체를 둔다. 상품 가격은 단순 환율 환산에만 의존하지 않고 시장별 확정 가격을 저장한다. 주문에는 주문 당시 가격·통화·정책 버전을 스냅샷으로 남겨 이후 설정 변경에도 과거 거래가 바뀌지 않게 한다.

관리자에는 전체/한국/베트남/헝가리 시장 선택을 제공한다. 상품·주문·쿠폰·통계를 같은 기준으로 연결한다. 재고는 초기에는 공통 SKU 재고를 유지하고 현지 창고가 생기면 창고별 재고와 출고 배정을 추가한다. 매출은 통화별로 분리하고 통합 보고서에는 환산 기준일과 환율을 별도로 표시한다.

## 단계

1. 현재 단계: 주문 국가 표시 및 서버 국가 필터. 운영 색인 배포 후 실제 관리자 조회 확인.
2. 판매 시장 모델과 고객 국가/언어 선택 UI. 시장 변경 시 장바구니 상품·가격을 재검증하고 서버에서 결제 조건을 확정.
3. 한국/헝가리 주소·배송·결제·반품 정책 설정 및 주문/환불 검증. 준비된 시장만 활성화.
4. `likedzy.com/kr/`, `/vn/`, `/hu/` 등의 시장별 URL과 검색 노출. 현재 HashRouter에서 주소 체계 전환과 기존 링크 호환 작업 필요.

기존 주문의 판매 시장은 증거가 있을 때만 출처를 남겨 보정한다. 과거 IP 국가는 임의 생성하지 않는다.
