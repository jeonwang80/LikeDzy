# 상품 이미지 잔존 원인과 수정 — 2026-09-30

## 운영 데이터에서 확인한 사실

공개 상품 문서를 읽기 전용으로 조회했다. 화면의 상품은 `zBs2wWNJoONTIpTHrBNB` (라이크디지 모션 반팔 폴로)이며 전체 이미지 12장, 색상 5개, ALL 공통 이미지 2장이 저장돼 있다.

- OFF WHITE&FROST BLACK의 상세 목록 3장 중 1장은 STARBUCKS GREEN의 대표 이미지와 동일하다. 흰색 앞·뒷면 아래 초록색 옷이 보이는 이유다.
- ZENITH BLUE의 상세 목록 3장 중 1장은 SMOKE BROWN의 뒷면 대표 이미지와 동일하다.
- 라벨 이미지는 ALL 공통 목록에 명시적으로 등록돼 있다. 각 색상에서 나타나는 것은 현재 설정에 따른 동작이며, 삭제했다는 사실이나 의도는 데이터만으로 확정할 수 없다.
- 별도 상품 2개에서도 전체 이미지 목록에서 빠진 주소가 색상별 대표/호버/상세 목록에 남아 있다. 기존 정규화는 전체 목록에 없는 주소를 표시 전에 걸러내지만, 저장 데이터에는 과거 연결이 남아 있다.

따라서 첨부 화면의 초록색 사진은 브라우저 캐시보다 저장된 중복 색상 연결로 설명된다. 운영 문서와 파일은 이번 조사에서 수정하지 않았다.

## 코드상 재발 경로

이미지 주소는 `imageUrls`, `commonImageUrls`, 색상별 `imageUrl` / `hoverImageUrl` / `imageUrls` / 예전 `images`, 예전 `colors` 등에 중복 저장된다.

1. 대표 역할을 바꾸는 처리에서 다른 색상의 예전 `images` 연결을 제거하지 않았다. 정규화가 이 주소를 다시 합칠 수 있었다.
2. 삭제 또는 색상 변경으로 빈 그룹이 생기면 정규화와 저장 처리에서 전체 이미지 중 하나를 순서에 따라 자동 배정했다. 다른 색상의 사진이 재연결될 수 있었다.
3. 중복 연결을 검증하지 않아 다른 색상의 대표 이미지가 일반 상세 사진으로 함께 표시됐다.
4. 화면 표시용 변환은 비어 있는 최신 목록을 예전 이미지 목록으로 대체하는 별도 경로를 갖고 있었다.

## 로컬 수정

- 색상 변경과 대표 역할 변경을 동일한 함수로 처리하고 현재·예전 연결을 함께 갱신한다.
- 명시적으로 빈 색상 목록에는 다른 색상 사진을 자동 배정하지 않는다. 오래된 그룹 필드가 없는 상품만 호환 추론을 유지한다.
- 다른 색상의 대표/호버로 지정된 사진은 해당 색상의 일반 상세 목록에서 제외한다. 전체 색상 공유는 ALL 목록으로 명시한다.
- 저장 시 순서 기반 자동 배정을 제거한다.
- 빈 전체 이미지 목록은 화면 변환에서도 빈 목록으로 유지한다. 이미지 없는 색상은 공통 사진 또는 자리표시자를 보여준다.

운영 데이터 복사본에 수정 함수를 적용하면 흰색·파란색 그룹은 각각 3장에서 2장으로 정리되며 전체 12장과 공통 2장은 유지된다. 공통 라벨을 없애려면 그 사진을 ALL에서 해제하거나 상품 전체 이미지에서 삭제해야 한다.

업로드 파일이 Storage에 남는 문제는 화면의 이미지 참조 문제와 별개다. 실제 파일을 제거할 경우 다른 상품·본문·주문 등의 참조 여부를 확인하는 별도 정리 절차가 필요하다. 이 수정은 참조를 정리하며 파일을 물리적으로 삭제하지 않는다.

## 검증 및 적용 상태

이미지 회귀 테스트 6개 통과, 수정 파일 ESLint와 배포 빌드 통과. 삭제→저장 데이터 직렬화→재로딩, 대표/호버/일반 역할 변경, ALL 이동, 빈 목록 유지와 색상 간 중복을 검증했다. 운영 배포 및 관리자 브라우저 조작 확인은 아직 수행하지 않았다.
