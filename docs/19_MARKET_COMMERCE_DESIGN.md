# LikeDzy 국가별 판매 운영 설계

작성: 2026-11-15 · 설계안. 이번 운영 배포는 주문 국가 조회와 로고 국가 코드 위치만 포함한다.

## 목표와 우선순위

사이트·관리자는 하나로 유지한다. 국가별 방문자가 구매 가능한 상품을 찾고 최종 금액과 배송 조건을 이해한 뒤 결제를 끝내도록 한다. 국가별 전환율과 기여이익으로 효과를 평가하며, 매출 상승을 보장하는 것으로 해석하지 않는다.

1. 구매 가능한 상품과 정확한 현지 가격을 먼저 보여준다.
2. 상품 상세에서 예상 배송일, 배송비/무료배송 조건, 교환·반품 조건을 알려준다.
3. 회원가입을 강제하지 않는 주문 흐름을 유지하고 현지 주소·결제 입력을 줄인다.
4. 국가별 유입 → 상품 조회 → 장바구니 → 결제 시작 → 결제 성공을 측정한다.

## 고객 흐름

첫 방문은 시장 URL, 기존 고객 선택, IP 추천 순으로 시장을 정한다. IP는 국적이나 확정 배송지가 아니다. 지원하지 않는 국가는 임의로 베트남으로 간주하지 않고 배송 국가 선택을 안내한다. 고객이 고른 언어는 시장과 독립적으로 유지한다.

헤더 로고의 작은 KR/VN/HU는 현재 IP 접속 국가 표시로 유지한다. 별도 선택 UI는 ‘배송 국가: 베트남 · VND / 한국어’처럼 의미를 명확히 한다. 추후 시장 선택 도입 시 기존 IP 구매 제한을 전환하는 작업이 필요하며 이번 배포에서는 기존 제한을 유지한다.

추천 배너는 한 번만 표시하고 닫을 수 있게 한다. 강제 전체화면 국가 선택과 반복 리디렉션을 피한다. 시장을 바꾸면 장바구니를 삭제하지 않고 판매 불가 상품과 가격 변동을 표시하여 확인받는다. 최종 주문 서버에서 시장 활성화, 배송지, 가격, 재고, 쿠폰, 결제 통화를 재검증한다.

판매 불가 시장에는 주문 버튼 대신 배송 가능 국가 변경 안내를 제공한다. 준비 중 시장을 열어 빈 상품 목록이나 결제 실패로 끝나게 하지 않는다. 현재 IP 정책을 변경하기 전에는 이 동작을 새 시장 정책으로 적용하지 않는다.

## 국가별 출시 계획

| 시장 | 기본 제안 | 출시 전 확정할 사항 |
| --- | --- | --- |
| 베트남 | vi, VND, 기존 운영 우선 개선 | 기존 계좌이체 유지, 현지 결제 추가 가능성, 배송 SLA, 반품 주소 |
| 한국 | ko, KRW | 판매 주체, 국내/해외 출고, 실제 결제 계약, 배송비·반품 비용 |
| 헝가리 | hu, HUF 제안, 영어 보조 | 현지 배송/반품, 카드 등 결제 제공사 지원, 정산 통화, 가격·세금 표시 검토 |

언어 지원이나 상품 판매 국가 체크만으로 시장을 출시하지 않는다. 결제·배송·환불을 실제로 처리할 수 있는 시장만 활성화한다. 결제 수단은 계약/국가 지원 여부 확인 후 결정하며 특정 현지 수단의 지원을 가정하지 않는다.

## 관리자 구성

- 공통 상단에 전체 / 한국 / 베트남 / 헝가리 시장 선택. 언어 선택은 별도로 유지.
- 시장 설정: 준비/시험/운영/중지, 통화, 판매 주체, 배송 국가, 배송비, 결제 방식, 반품 안내, 기본 언어.
- 상품: 공통 SKU·이미지·재고와 시장별 판매 여부·확정 판매가·할인가·노출 순서·카피를 분리.
- 주문: 판매 시장을 주요 분류로, IP 국가/배송 국가를 보조 정보로 표시. 현재 주문은 두 국가만 조회 가능.
- 쿠폰: 적용 시장·통화·최소 금액·중복 사용·기간을 명시. 다른 통화 쿠폰을 임의 환산하지 않음.
- 통계: 시장별 결제 완료 매출, 환불, 주문 수, 객단가, 전환율, 배송비 부담. 서로 다른 통화 숫자를 그대로 합산하지 않음.

## 데이터 및 서버 설계

`markets/{KR|VN|HU}`: status, currency, defaultLanguage, allowedLanguages, shippingCountries, paymentMethods, shippingPolicyVersion, returnPolicyVersion, sellerId.

`products/{id}/marketOffers/{market}`: enabled, currency, price, compareAtPrice, promotionStart/End, displayOrder. 공통 SKU 재고는 중복 생성하지 않는다. 창고가 추가되면 별도 inventoryLocations와 예약/출고 배정을 둔다.

`orders/{id}` 스냅샷: marketCode, accessCountry, shippingCountry, language, currency, sellerId, pricingVersion, shippingPolicyVersion, items의 확정 단가/할인, 배송비, 최종 금액, 결제 방법/상태. 실제 결제 성공 콜백은 멱등 처리하고 금액·통화를 서버 대조한다.

현재 `salesCountry`는 검증된 IP 국가이며 선택 시장이 아니다. 신규 스키마에서는 accessCountry로 명확히 하고 기존 필드는 호환 읽기를 유지한다. 기존 `country`는 배송 국가로 읽는다. 과거에 없는 IP/판매 시장을 통화나 언어만 보고 채우지 않는다.

시장 설정 수정 권한과 변경 이력을 관리자에 제한한다. 구매자가 보낸 가격·환율을 신뢰하지 않는다. 결제 실패/만료 시 예약 재고 해제, 성공 후 환불과 재고 복원은 별개 상태로 처리한다.

## 판매 개선 실험과 측정

초기에는 과도한 할인보다 배송 정보·사이즈 안내·현지 통화의 명확성을 우선한다. 상품 상세에 소재/핏/실측과 착용 정보를 제공하고 모바일 장바구니 버튼을 쉽게 찾게 한다. 무료배송 기준은 객단가·원가·배송비·반품비를 바탕으로 결정하며 임의 금액을 제시하지 않는다.

이벤트: product_view, add_to_cart, checkout_start, payment_attempt, payment_success, payment_failure, refund. marketCode/currency/device와 익명 세션을 연결하고 개인정보를 이벤트 속성에 넣지 않는다. 결제 성공은 서버 이벤트로 중복 제거한다. 분석 수집은 적용되는 동의 설정과 연동한다.

주요 지표: 결제 완료 주문/방문 세션, 장바구니/상품 조회, 결제 완료/결제 시작, 실패 사유, 환불률, 주문당 기여이익. IP 국가별 분석과 판매 시장별 분석을 분리한다. 은행이체는 주문 생성과 입금 확인을 구분한다.

먼저 2~4주 기준 데이터를 확보하고 한 번에 한 개선을 시험한다. 유입이 적으면 짧은 기간의 수치 차이를 효과로 단정하지 않고 고객 문의·실패 로그를 함께 분석한다.

## 구현 순서와 출시 조건

1. 이번 배포: 국가 조회/필터, 로고 국가 코드 위치. 색인 준비 후 프런트 배포.
2. 시장 설정/주문 스냅샷 및 국가·언어 선택. 시험 환경에서 시장 전환과 장바구니 재계산 검증.
3. 베트남을 먼저 전환. 기존 주문 조회, 계좌이체, 재고 예약, 쿠폰, 환불 회귀 검증.
4. 한국·헝가리 각 시장의 가격·결제·배송 준비 후 제한된 시험 주문. 실제 결제/취소/환불/배송을 모두 확인한 시장부터 공개.
5. 시장 URL 및 검색 노출 개편. 현재 HashRouter 링크 호환, canonical/hreflang, 리디렉션과 검색 봇 접근을 함께 설계.

출시 점검: 미지원 시장 안내, VPN/미확인 IP, 다른 언어 사용, 품절, 할인 종료, 통화 불일치, 결제 재시도/중복 콜백, 모바일 320~430px, 재고 경쟁, 구 주문 조회. 장애 시 해당 시장 신규 주문만 중지하고 기존 주문·배송·환불 처리는 계속 가능해야 한다.

## 근거와 결정이 필요한 운영 정보

[Shopify 공식 현지화 안내](https://help.shopify.com/en/manual/markets/getting-started/localization)는 IP 추천과 수동 국가·언어 선택을 함께 설명한다. [Zara 배송 안내](https://www.zara.com/us/en/help-center/DeliveryMethods)는 판매 시장과 배송 지역의 일치를 요구한다. 위 상세 설계는 이러한 공개 흐름을 참고한 LikeDzy 제안이며 해당 기업의 내부 구현을 확인한 것이 아니다.

다음 구현 전에 판매 주체, 국가별 출고/반품 장소, 현지 판매 가격과 목표 마진, 결제 계약 가능 여부, 배송 소요일/비용을 확정해야 한다. 이 정보가 없으면 시장 상태를 준비로 유지한다.
