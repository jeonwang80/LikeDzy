# 한국·베트남 스토어 통화 구성 (2026-09-28)

- 고객 언어 선택: 한국어 / KRW, English / VND. 베트남어 선택은 제거했으며 저장된 번역 데이터는 보존한다.
- 기본 언어는 한국어다. 선택은 브라우저에 저장하며 기존 vi 선택은 en으로 연결한다.
- 영어 상품·정렬·장바구니·주문은 VND 판매가를 사용한다. 원화·달러를 VND로 대신 해석하지 않는다. 가격이 없으면 구매 금액을 확정하지 않는다.
- 관리자 상품 가격은 KRW와 VND를 각각 입력한다. 고정 환율 자동 환산을 제거하여 한 통화 편집으로 다른 판매가를 덮어쓰지 않는다.
- `settings/commerce.vietnam`에 VND 배송비, 무료배송 기준, 계좌, 영어 정책, 정책 확인과 주문 활성화를 따로 관리한다. 사업자 정보는 공통이다. 기존 한국 설정은 유지한다.
- VND 배송 설정·계좌·정책이 미완성이면 주문을 개방하지 않는다. 실제 판매 개방에는 기존 App Check 및 재고 준비 조건도 필요하다.
- 주문 요청에 currency를 전달하고 서버가 해당 통화 상품 가격과 배송비로 재계산한다. 통화가 바뀐 동일 요청 키는 거부한다. KRW 요청의 기존 fingerprint와 호환된다.
- 주문 조회·관리·환불은 저장된 주문 통화를 사용한다. 통화가 없는 과거 주문은 KRW로 취급한다.
- VND 배송지 우편번호는 선택 사항이고 한국 주소 검색·현금영수증 신청은 한국어 KRW 주문에서만 표시한다.

## 검증

코드 검사와 운영 빌드 성공. 통화별 서버 계산, 재시도, 환불, 잘못된 통화·가격·설정 차단과 기존 KRW 호환 테스트를 추가했다. 운영 데이터의 가격·계좌·판매 개방 설정은 이번 코드 변경으로 수정하지 않는다.

## 배포

Functions를 먼저 반영한 뒤 프런트엔드를 배포해야 한다. 기존 KRW 요청도 지원하므로 이 순서로 호환성을 유지한다. 운영 배포 결과는 배포 기록에 기재한다.

## 헝가리어 및 접속 국가 표시 — 2026-11-15

- 헤더 로고 앞에 ISO 2자리 접속 국가를 표시한다. `/api/visitor-country`가 Vercel의 `x-vercel-ip-country` 헤더를 읽으며 응답은 `private, no-store`다. 국가를 확인할 수 없는 로컬 개발 환경/오류에서는 `--`를 표시한다. IP 자체는 저장하지 않는다. VPN 이용 시 VPN 접속 국가가 표시될 수 있다.
- 접속 국가와 언어 선택은 독립적이다. 고객 언어 선택에 Magyar(hu)를 추가했다. 접속 국가만으로 자동 리디렉션하거나 결제 국가를 바꾸지 않는다.
- 상품 편집 탭은 한국어/English/Tiếng Việt/Magyar를 지원하며 상품의 hu 객체에 이름·설명을 저장한다. 고객 상품 표시는 필드별 hu → en → ko 순서로 빈 번역을 보완한다.
- 카테고리 그리드는 선택한 언어의 명칭만 표시한다. 코드·정렬·활성 여부는 공통이며 탭 변경으로 미저장 내용을 잃지 않는다. `level1NameHu`, `level2NameHu`, `level3NameHu`를 추가했다. 한국어 명칭 필수 조건은 유지한다.
- 기본 카테고리에는 헝가리어 표시값을 제공한다. 관리자 입력값이 우선이며 기존 데이터는 자동 덮어쓰지 않는다. hu 이름순 조회는 기존 영어 정렬 필드를 사용한다.
- 주요 탐색·홈·공통 구매 문구를 헝가리어로 추가했다. 전체 문구의 번역 완료를 의미하지 않으며 미번역 시스템 문구/관리자 등록 콘텐츠는 기존 영어 또는 원문을 표시할 수 있다. 이미지 안의 문구는 별도 이미지가 필요하다.
- 이번 변경은 헝가리 판매 개방, HUF 통화, 배송·결제 정책 변경을 포함하지 않는다.
- 검증: 운영 빌드, 국가 헤더/미확인 국가 응답 및 번역 fallback 검증, 격리된 카테고리 UI에서 탭 전환 후 입력 유지와 다국어 저장 payload 보존 확인. 실제 IP 기반 국가 표시는 Vercel 배포 후 확인해야 한다.

## 상품별 판매 국가 — 2026-11-15

- `products.salesCountries` 배열에 `KR`, `VN`, `HU`를 저장한다. 상품 관리 목록의 체크박스는 즉시 저장하고 상품 편집에서는 저장 버튼으로 반영한다. 필드가 없는 기존 상품 및 신규 상품의 기본값은 `['VN']`이다. 명시적 빈 배열은 전 국가 판매 제외이며, 잘못된 값도 허용하지 않는다.
- 선택 언어나 배송지가 아니라 Vercel이 확인한 접속 IP 국가로 목록·상세·장바구니 추가·주문을 제한한다. 국가 미확인 및 지원하지 않는 국가는 판매 대상에서 제외한다. VPN을 사용하면 VPN 출구 국가로 인식한다. 판매 중지 및 재고 제한도 계속 적용한다.
- 현재 29개 상품 규모에서는 Firestore 실시간 구독 결과를 국가/분류별로 먼저 필터링하고 페이지를 나눈다. 국가별 상품이 섞여 있을 때 빈 페이지가 생기는 문제를 피하고 설정 변경을 즉시 반영한다. 대규모 카탈로그로 확장할 때는 국가 필드 백필과 서버 필터/인덱스 및 커서를 함께 도입해야 한다.
- IP 국가는 헤더와 쇼핑 화면에서 공유하며 1분마다 갱신한다. 주문 직전에는 `/api/visitor-country` POST로 다시 확인한다. 이 API는 주문 시도 키에 묶인 5분 유효 HMAC 증명을 발급하고, Firebase 주문 함수가 이를 검증한 뒤 최신 상품 설정을 재검사한다. 요청 본문의 임의 국가 값은 신뢰하지 않는다. 신규 주문에 확인한 국가를 `salesCountry`로 기록하며 배송지 `country`와 구분한다. 이미 생성된 주문의 재시도·조회는 기존 복구 규칙을 유지한다.
- 주문 서버는 검증 키/증명이 없으면 신규 주문을 거부한다. Vercel 서버 환경 변수와 Firebase Secret Manager에 **동일한 `COUNTRY_TOKEN_SECRET`** (무작위 32바이트 이상)을 설정해야 한다. 브라우저용 VITE 변수나 저장소에 넣으면 안 된다. Firebase `createBankTransferOrder`만 해당 secret을 바인딩한다.
- 배포 순서: 동일 secret을 두 플랫폼에 설정 → Vercel 프런트/API 배포 → Firebase `createBankTransferOrder` 배포 → 실국가 및 허용/거부 주문 확인. 프런트와 함수가 모두 반영되기 전에는 서버 제한이 완전히 활성화되지 않는다. 배포 후 과거 탭은 새로고침해야 한다. 키가 없는 상태로 함수부터 배포하지 않는다.
- 한국/헝가리 체크는 해당 국가 접속자의 상품 접근 허용 설정이다. 배송·통화 정책은 별개이므로 현재 베트남 배송/VND 주문 정책을 바꾸지 않는다. 원본 Firestore 상품 읽기 권한을 비공개로 변경하는 기능은 아니다.
# 주문 국가 분류 (2026-11-15)

주문 관리에 IP 접속 국가(`salesCountry`)와 배송 국가(`country`)를 구분하여 표시하고 국가/상태 복합 필터를 추가했다. 과거 IP 미기록 주문은 전체 국가 조회에 포함한다. 운영 반영 전에 orders 복합 색인 4개의 생성 완료를 확인해야 한다. 글로벌 개편 권고는 [18_GLOBAL_MARKETS_REVIEW.md](18_GLOBAL_MARKETS_REVIEW.md)를 참고한다.

로고의 IP 국가 코드는 로고 오른쪽 하단에 배치한다. 판매 전환 중심의 시장 운영 설계는 [19_MARKET_COMMERCE_DESIGN.md](19_MARKET_COMMERCE_DESIGN.md)를 참고한다. 설계안의 시장 선택·가격·결제 개편은 이번 배포 범위가 아니다.
