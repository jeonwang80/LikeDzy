# Account and coupon operations

- Members can store a name, contact number and one default delivery address in My account. During the Vietnam launch, checkout accepts only Vietnam addresses and VND prices; a saved Korean address is not applied.
- Admins create a coupon at Admin → Coupons. Set code, market currency, percent, minimum product subtotal, maximum discount, total redemption count and local start/end time. The initial form suggests 30% for VND and enables **new member auto issuance**. No campaign becomes active until an admin saves it.
- Firebase Auth's new-user event issues eligible auto coupons once to users whose account creation time falls within the campaign period. Existing members are not backfilled. The coupon appears in My account and at checkout shortly after signup, including a first Google sign-in that creates a new account.
- Customers must sign in to apply a coupon code at checkout. Auto-issued codes additionally require a matching member entitlement. The UI displays a quote. The server recomputes the discount against current product prices and records the discounted amount. One member can use a code once; unpaid cancellation or expiry restores it.
- Coupon amounts are in the selected currency. Existing order prices and historical order names are snapshots and do not change when the site language changes.

## 2026-10-04 checkout and coupon review

- A member can hold up to three available, scheduled, paused or pending-payment coupons. Used/expired/exhausted coupons remain in history but do not consume a slot. Existing holdings are never deleted. Issuance checks current campaigns in a transaction and locks one wallet document per member, shared by signup and manual grants. Pending-payment reservations keep a slot so cancellation can restore the coupon.
- Admin → Members includes held/available/used counts and expandable code, status, dates and discount conditions. Customer My account and checkout use authenticated `listMyCoupons`, which derives current terms from the campaign and distinguishes pending payment from completed use. Refresh occurs on entitlement changes, focus and every 60 seconds.

Code/currency are fixed, usage/creation records are preserved transactionally, and a limit lower than current usage is rejected. Input times use the displayed browser timezone. Existing order totals are not rewritten.

## Member order statements

- My account order cards include View statement. An accessible modal reads the selected order through the existing owner-authorized Firestore rules and a live onSnapshot subscription. It also requires the document userId to match the signed-in member. Missing, deleted or inaccessible orders clear the displayed statement and show a retryable error.
- Statements use stored order snapshots: item/options/quantity/unit price, subtotal, delivery fee, coupon discount/code, final amount, bank details, payment status/dates and delivery address. Older records retain their original currency; missing breakdown values show an em dash rather than invented amounts.
- Print / Save PDF invokes the browser print dialog. Print CSS includes only the statement and hides the toolbar, member page and navigation. Keyboard focus is contained in the modal and restored to its opening button on close; background content is inert while open.
