01 / PRODUCT

상품 등록과 이미지 연결

관리자 → 상품 관리 → 새 상품 등록 또는 편집

상품 관리 ↗
  1. 기본 정보를 입력합니다.

    상품명, 카테고리, 설명과 통화별 판매가를 입력하세요. 베트남 판매에는 VND 가격이 사용됩니다. 언어별 상품명·설명도 확인합니다.

  2. 색상과 사이즈를 정합니다.

    실제 판매할 색상명과 컬러칩을 등록하세요. 두 가지 색상은 투톤으로 지정할 수 있습니다. 사이즈 옵션과 가이드의 치수가 맞는지 확인하세요.

  3. 사진을 색상에 연결합니다.

    이미지 연결 · 미리보기에서 사진 카드의 적용 색상을 선택합니다. 대표 1은 첫 사진, 대표 2는 마우스를 올렸을 때 보이는 사진입니다. ALL은 모든 색상에서 사용하는 공통 일반 이미지입니다.

  4. 저장한 뒤 재고를 입력합니다.

    미리보기에서 색상을 바꿔 사진과 가격을 확인한 후 저장 및 반영을 누르세요. 목록의 재고 버튼에서 판매가능 수량을 등록합니다.

노출 배지

추천NEWBEST

상품 목록이나 편집 화면에서 설정합니다. 추천은 메인 노출 우선순위에 사용되고, 신상품·베스트는 배지로 표시됩니다.

저장 전 확인

  • 선택한 색상과 대표 사진이 일치하나요?
  • VND 판매가와 옵션명이 정확한가요?
  • 모바일에서 설명과 사진이 잘 보이나요?
사진 배경색 설정

이미지 연결 · 미리보기의 각 사진에서 자동 배경색을 누르면 가장자리 색을 추출합니다. 사진에서 색 선택을 누른 뒤 확대된 사진의 원하는 지점을 클릭하거나 터치하면 그 색을 배경으로 지정합니다. 직접 지정의 색상 선택기로 조절할 수도 있습니다. 초기화는 기본 배경으로 되돌립니다.

사진 비율은 유지하며 주변 빈 공간의 색만 바뀝니다. 사진별 설정이 색상 전환·호버·상세 사진에도 연결됩니다. 그라데이션 배경은 경계가 남을 수 있습니다. 자동 추출 실패 시 직접 지정해 주세요.

미리보기는 편집 중인 상태입니다.

사진 연결·상품 정보·배경색은 저장 및 반영까지 완료해야 고객 화면에 반영됩니다. 상품 관리에서 저장하는 콘텐츠는 별도의 사이트 배포 없이 반영됩니다.

0등록된 옵션이지만 현재 품절입니다.

  1. 변경할 칸만 수정합니다.

    예를 들어 판매가능 재고가 3개이고 2개를 추가 입고했다면 5로 입력합니다.

  2. 변경사항 저장을 누릅니다.

    수정한 칸만 저장됩니다. 다른 주문·관리 작업으로 값이 바뀌었다는 안내가 나오면 최신 수량을 다시 확인하세요.

  3. 목록의 합계를 대조합니다.

    총 재고는 현재 상품의 색상·사이즈 조합만 합산합니다. 예전에 삭제하거나 이름을 바꾼 옵션의 재고는 현재 합계에서 제외됩니다.

색상·사이즈 이름을 바꿨다면 재고도 확인하세요.

이전 옵션의 수량이 새 이름으로 자동 이전되지는 않습니다. 변경한 옵션의 실물을 대조해 수량을 다시 등록하세요. 과거 주문·재고 기록은 이력으로 남습니다.

판매 중지

새 주문 접수를 멈출 때

판매 중지 버튼을 누릅니다. 중지된 상품은 목록에서 회색 행과 상태 배지로 구분됩니다. 기존 주문 처리는 별도로 진행합니다.

판매 재개

판매를 다시 시작할 때

가격·옵션·재고를 확인한 뒤 재개합니다. 재고가 없으면 스토어에는 상품 준비중으로 표시될 수 있습니다.

고객 화면의 판매 준비 상품은 회색 음영과 하단 배지로 구분됩니다. 이미지 중앙에는 중복 문구를 표시하지 않습니다.

04 / STOREFRONT

메인 화면과 이벤트 팝업

관리자 → 운영 홈

운영 홈 ↗

신상품 · 이벤트 팝업 설정

  1. 팝업 노출과 기간을 설정합니다.

    시작·종료 시간을 지정할 수 있습니다. 시간은 관리자 기기의 시간대를 기준으로 입력합니다. 기간을 비우면 해당 시작·종료 제한이 없습니다.

  2. 사진 3장과 안내 문구를 넣습니다.

    신상품 이미지, 한국어·영어 문구, 상품 보기 이동 주소를 설정합니다. 사진은 JPG·PNG·WebP, 파일당 10MB 이하를 사용하세요. 이동 주소는 스토어 내부 경로를 입력합니다.

  3. 한국어·English 미리보기 → 팝업 저장

    할인 문구, 사진 잘림, 연결되는 상품을 확인하고 저장합니다. 사진을 업로드한 뒤에도 팝업 저장까지 완료하세요.

팝업은 언제 나타나나요?

홈 화면에서 진입 인트로가 끝난 뒤 노출됩니다. 상품 상세·주문서·관리자 화면에는 뜨지 않습니다.

닫기·상품 보기 후에는 같은 탭에서 다시 뜨지 않습니다. ‘오늘 하루 보지 않기’는 고객 기기의 자정까지 적용됩니다.

메인 배너와 진입 인트로

메인 배너 이미지 관리에서 가로 사진을 추가합니다. 여러 장은 자동 슬라이드됩니다. 제목·서브 내용과 크기는 텍스트 저장으로 반영합니다.

진입 인트로 비주얼 관리에서 첫 진입 화면의 이미지를 관리합니다.

‘30% 할인’ 문구와 쿠폰은 따로 설정합니다.

팝업 문구만 바꿔서는 할인이나 쿠폰 지급이 시작되지 않습니다. 쿠폰 메뉴의 할인율·기간·발급 조건과 맞추세요. 문구 수정만으로 이미 닫은 고객에게 팝업이 다시 열리지는 않습니다.

05 / ORDER

입금 확인부터 배송 완료까지

관리자 → 주문 관리 → 상세

주문 관리 ↗
입금 대기→입금 확인→상품 준비중→발송 완료→배송완료
  1. 입금 대기 주문을 확인합니다.

    목록은 최신순, 페이지당 50건입니다. 상태 필터로 입금 대기를 선택하고 상세에서 주문 상품·옵션·수량, 쿠폰 할인 후 최종 금액, 입금자와 입금기한을 확인합니다.

  2. 은행 내역을 확인하고 입금 확인으로 변경합니다.

    실제 입금액과 입금자명을 주문과 대조하세요. 확인하면 예약 재고가 판매 수량으로 전환됩니다. 기한이 지난 주문의 입금은 바로 확정할 수 없으므로 주문 상태와 은행 내역을 따로 대조해야 합니다.

  3. 상품을 준비하고 송장을 저장합니다.

    상태를 상품 준비중으로 변경합니다. 택배사·송장번호를 입력한 뒤 송장 저장을 누르세요. 입금 확인 이후부터 송장을 등록할 수 있습니다.

  4. 실제 발송 후 상태를 갱신합니다.

    송장이 저장되어 있어야 발송 완료로 변경할 수 있습니다. 배송 결과를 확인한 뒤 배송완료로 처리합니다. 배송 조회 링크도 확인하세요.

수기 입금 운영의 핵심

시스템은 은행 입금을 자동 확인하지 않습니다. 입금 확인은 운영자가 실제 입금을 확인했다는 기록입니다. 주문서의 계좌·QR을 확인하고, 고객에게는 주문 접수 후 확정된 최종 금액으로 입금하도록 안내하세요.

실물을 받은 후 검수 내용을 입력하고 재판매 가능한지 판단합니다. 재입고를 선택하면 수량이 복원됩니다. 상품을 받기 전에 입고 처리하지 마세요.

환불 완료 기록

고객과 반환 계좌를 확인하고 은행에서 전액 환불한 뒤, 실제 금액과 이체 확인번호를 입력합니다. 현재 화면은 전액 환불 기록을 지원합니다.

환불 버튼은 송금하지 않습니다.

은행 환불을 먼저 완료해야 합니다. 현금영수증 항목도 외부 발급·취소 후 확인번호를 기록하는 기능입니다.

입금기한이 지난 미입금 주문은 만료 처리 대상입니다. 취소되면 예약 재고와 사용 중인 쿠폰이 해제됩니다. 쿠폰은 현재 유효기간·잔여 한도를 충족해야 다시 쓸 수 있습니다.

07 / COUPON

쿠폰을 만들고, 필요하면 수정하세요.

관리자 → 쿠폰

쿠폰 관리 ↗
  1. 코드와 할인 조건을 입력합니다.

    쿠폰 코드, 이름, 통화, 할인율, 최소 주문금액, 최대 할인금액, 전체 사용 한도를 설정합니다. 베트남 주문용은 VND를 선택하세요.

  2. 기간과 자동 지급 여부를 설정합니다.

    시작·종료 일시는 관리자 기기의 현지 시간 기준입니다. 신규 가입 자동 지급을 사용하려면 해당 옵션과 쿠폰 활성 상태를 확인합니다.

  3. 발급 후에도 수정할 수 있습니다.

    목록의 수정에서 이름·날짜·할인 조건·한도를 변경합니다. 코드와 통화는 변경할 수 없습니다. 사용 한도는 이미 사용된 수보다 낮게 줄일 수 없습니다.

  4. 고객 화면에서 할인 결과를 확인합니다.

    로그인 → 주문서 → 쿠폰 선택 또는 코드 적용 후, 할인금액과 최종 입금액이 바뀌었는지 확인하세요. 적용 실패 안내가 있으면 할인된 것으로 판단하지 마세요.

계산 예시 · 최대 할인 한도가 충분할 때

790,000 ₫ 상품에 30% 쿠폰

상품금액 790,000 − 할인 237,000 + 배송비 0

553,000 ₫

실제 할인은 최소 주문금액·최대 할인액·기간·잔여 한도에 따라 달라집니다. 최대 할인액이 100,000 ₫이면 위 예시의 최종 금액은 690,000 ₫입니다.

이미 접수된 주문 금액은 바뀌지 않습니다.

쿠폰 조건을 수정해도 기존 주문의 확정 금액은 유지됩니다. 새 주문에는 수정한 조건이 적용되고, 접수 시 서버에서 조건을 다시 확인합니다. 주문당 쿠폰은 1개입니다.

쿠폰 상태 읽는 법

상태확인할 내용
사용 가능기간·조건·잔여 한도가 맞는 쿠폰입니다.
사용 시작 전시작일을 확인합니다. 발급됐어도 시작 전에는 적용할 수 없습니다.
기간 만료 / 사용 중지종료일과 활성 상태를 쿠폰 메뉴에서 확인합니다.
소진전체 쿠폰 사용 한도를 확인합니다. 개인이 사용한 적이 없는 경우도 전체 한도에 영향을 받습니다.
입금 대기 주문에 적용진행 중인 주문에 연결된 상태입니다. 해당 미입금 주문을 취소하면 해제됩니다.
사용 완료해당 회원의 사용 이력을 확인합니다. 발급 여부만으로 사용 완료가 되지는 않습니다.
08 / MEMBERS

회원과 쿠폰 보유 현황

관리자 → 가입자 현황

가입자 현황 ↗
3개

회원당 최대 보유 쿠폰

사용 가능·시작 전·중지·입금 대기 주문에 적용된 쿠폰이 보유 한도에 포함됩니다. 사용 완료·만료·소진 이력은 한도에서 제외됩니다.

신규 가입 자동 지급 확인

  1. 쿠폰이 활성화되어 있고 기간 내인지 확인합니다.
  2. 신규 가입 자동 지급 옵션을 확인합니다.
  3. 가입자 현황에서 해당 회원의 쿠폰을 펼쳐 코드·상태·기간을 확인합니다.

새 이메일 가입과 최초 Google 계정 생성이 대상입니다. 기존 회원에게 소급해서 자동 지급되지는 않습니다.

기존 회원에게 직접 지급

  1. 이메일로 정확히 검색하거나 목록에서 회원을 선택합니다.
  2. 선택 회원에게 쿠폰 지급 영역에서 쿠폰을 고릅니다.
  3. 지급 버튼을 누르고 결과 및 보유 내역을 확인합니다.

같은 코드는 회원당 한 번 지급됩니다. 이미 보유 한도가 찼다면 추가 지급할 수 없습니다.

목록은 50명씩 표시되며 상단 집계는 현재 조회 페이지 기준입니다. 이메일 인증 상태와 계정 사용 상태도 함께 확인할 수 있습니다.

09 / CUSTOMER CARE

문의에 답하고 리뷰를 확인합니다.

관리자 → 고객 응대

고객 응대 ↗
  1. 문의 탭에서 내용을 확인합니다.

    상품과 작성 내용, 비밀글 여부를 확인한 뒤 답변 작성을 선택합니다.

  2. 답변을 등록하고 고객 화면을 확인합니다.

    답변 등록으로 저장합니다. 기존 답변은 답변 수정하기에서 고칠 수 있습니다. 비밀 문의는 작성한 계정과 관리자에게만 보입니다.

  3. 리뷰 탭에서 평가와 사진을 확인합니다.

    고객 리뷰는 로그인 후 작성하며 사진은 최대 4장 첨부할 수 있습니다. 삭제는 실제 게시물에 반영되므로 대상 글을 확인하세요.

고객이 답변을 못 찾는다면

문의를 작성한 계정으로 로그인했는지, 답변을 작성만 하고 등록하지 않은 것은 아닌지 확인하세요. 이전 방식으로 작성된 문의는 고객센터를 통해 별도 확인이 필요할 수 있습니다.

현재 판매 범위

신규 주문은 베트남 배송만 접수하며, 배송비는 무료이고 최종 입금액은 VND입니다.

고객이 한국어를 선택해도 배송 국가·통화가 한국으로 바뀌지는 않습니다. 한국 주문 재개에는 별도 운영 변경이 필요합니다.

카테고리 정리

기준정보에서 카테고리 코드, 분류명, 언어별 표시명, 순서와 사용 여부를 관리합니다. 저장한 사용 중 카테고리를 상품 편집에서 선택합니다. 분류를 바꾼 뒤 스토어 목록과 해당 상품을 확인하세요.

관리자 추가와 계정 관리

관리자 승인 계정 관리에서는 Firebase 인증 사용자 목록에서 확인한 회원 고유 UID를 등록합니다. 이메일 주소를 입력하는 방식이 아닙니다. 해당 계정의 이메일 인증을 완료한 뒤 로그인해 권한을 확인하세요.

관리자 상단의 비밀번호 변경은 로그인 계정으로 재설정 이메일을 보냅니다. Google 등 외부 로그인 계정은 해당 로그인 방식도 확인하세요.

운영 정책은 실제 내용으로 관리하세요.

고객 안내, 개인정보 처리 내용, 배송·반품 정책은 실제 운영 방식과 맞춰 작성합니다. 초기 수기 운영 모드의 주문 가능 여부와 정책 검토는 별개의 관리 항목입니다.

11 / CUSTOMER EXPERIENCE

고객에게 이렇게 안내하세요.

주문 조회와 전표

회원은 마이페이지의 주문 내역에서 전표를 열어 주문 상품, 금액과 상태를 확인합니다. 전표의 인쇄 기능으로 인쇄하거나 PDF로 저장할 수 있습니다.

비회원은 주문 접수 때 제공된 조회·복구 정보를 보관해야 합니다. 조회 정보는 다른 사람에게 공유하지 않도록 안내하세요.

내 정보와 쿠폰

마이페이지에서 회원 정보, 기본 배송지, 보유 쿠폰과 주문 내역을 확인합니다. 베트남 주문서에는 베트남 배송지 정보를 사용합니다.

쿠폰은 로그인한 회원의 보유 상태와 실제 주문 조건을 함께 확인해야 적용됩니다.

화면에서 직접 저장하는 것

관리자의 상품·카테고리·팝업·쿠폰 행사 설정, 고객의 본인 프로필·문의·리뷰는 Firebase SDK와 보안 규칙을 통해 저장합니다. 사진 파일은 Storage에, 파일 주소·경로는 Firestore에 기록합니다.

서버에서 확정하는 것

주문 생성, 재고 변경, 쿠폰 사용·발급, 입금·배송 상태 변경은 Cloud Functions에서 확인합니다. 브라우저가 표시한 금액을 그대로 믿지 않고 상품 가격·재고·쿠폰 조건을 다시 계산합니다.

주문 한 건이 접수되는 흐름

  1. 고객이 주문서를 제출합니다.

    장바구니의 상품·옵션·수량, 배송 정보, 예상 금액과 요청 식별값을 서버로 보냅니다. 쿠폰 적용 화면의 금액은 먼저 계산한 예상값입니다.

  2. 서버가 최신 데이터를 확인합니다.

    createBankTransferOrder가 판매 설정, 상품 가격, 현재 옵션, 판매가능 재고와 쿠폰을 검증합니다. 화면 금액과 다르면 다시 확인하도록 안내합니다.

  3. 연관 데이터를 함께 저장합니다.

    하나의 트랜잭션에서 주문 생성, 재고 예약, 공개 재고 갱신, 쿠폰 사용 연결과 이력을 기록합니다. 함께 성공하거나 함께 취소되어 데이터가 일부만 저장되는 상황을 막습니다.

  4. 접수 결과를 조회하고 운영자가 처리합니다.

    회원은 본인 주문으로, 비회원은 복구 정보로 조회합니다. 이후 운영자의 입금 확인·취소·발송 처리에 따라 주문과 재고가 갱신됩니다.

같은 요청을 다시 보내도 중복 주문을 만들지 않도록 관리합니다.

주문과 재고 저장 요청에는 요청 식별값이 있습니다. 응답이 늦거나 연결이 끊겼을 때 기존 처리 결과를 확인할 수 있도록 별도 기록을 보관합니다. 재고의 version 값은 오래된 화면에서 최신 수량을 덮어쓰지 않게 합니다.

프로그램 배포와 운영 데이터 저장의 차이

바꾸는 것반영 경로
상품·쿠폰·계좌·팝업 내용관리자에서 저장 → Firestore / Storage → 고객 화면에서 조회·구독
화면 디자인·기능·매뉴얼소스 수정 → Vite 빌드 → Vercel 운영 반영 + Firebase Hosting 배포
주문 처리·권한·데이터 규칙서버 함수 또는 Firebase 규칙·색인 수정 → 해당 항목 별도 배포

운영 배포는 생성된 배포본의 Production 상태를 확인합니다. 프런트 화면 배포만으로 서버 함수나 데이터베이스 규칙이 자동 변경되지는 않습니다.

14 / DATA RELATIONSHIPS

데이터 관계도 · ERD

현재 코드가 사용하는 주요 연결을 두 장으로 나누었습니다.

Firestore는 관계형 테이블이 아닌 문서 데이터베이스입니다.

아래 ERD는 문서 ID와 참조 필드로 연결되는 논리적 관계입니다. SQL의 외래키 제약이나 자동 연쇄 삭제가 설정된 그림은 아닙니다. items[] 같은 배열은 문서 안에 저장되며, 그림의 REF는 코드에서 사용하는 참조를 뜻합니다.

ERD 01

상품 · 옵션 재고 · 변경 이력

크게 보기 ↗
연결관계와 의미
카테고리 → 상품카테고리 하나에 상품 여러 개. 상품의 categoryMasterId는 선택 항목이며 기존 상품은 카테고리 코드만 가질 수 있습니다.
상품 → inventory상품 하나에 색상 × 사이즈별 재고가 여러 개. 문서 ID variantId는 상품·색상·사이즈 조합을 식별합니다.
inventory → 공개 재고stockAvailability는 같은 문서 ID를 사용합니다. 서버가 stock을 공개용 available 값으로 함께 갱신합니다.
inventory → 변경 이력inventoryMovements에 수량 증감과 변경 후 값을 기록합니다. 주문 관련 변경에는 orderId도 포함됩니다.
상품·재고 → 주문 항목orders.items[]는 productId와 variantId를 보관합니다. 상품명·단가·수량도 주문 당시 값으로 복사합니다. 별도 orderItems 컬렉션은 없습니다.
ERD 02

회원 · 주문 · 쿠폰

크게 보기 ↗
연결관계와 의미
Auth → users계정 하나에 선택적으로 프로필 하나. users/{uid}에는 연락처·기본 배송지를 저장하며 로그인 계정 자체는 Auth가 관리합니다.
Auth → orders회원 하나에 여러 주문. 비회원 주문은 userId가 비어 있어도 생성됩니다.
orders → orderEvents주문 하나에 생성·상태 변경 등의 이벤트가 누적됩니다. 현재 상태는 orders, 처리 이력은 orderEvents에서 관리합니다.
Auth + coupons → userCoupons회원과 쿠폰 코드 조합당 발급 문서 하나. 보유 한도 3개는 상태를 계산한 결과이며 문서 총개수 제한이 아닙니다.
Auth + coupons → couponUses회원과 코드 조합당 사용 상태 문서 하나. orderId로 연결 주문을 기록하고 미입금 취소 시 released가 변경됩니다.
coupons → orders주문당 쿠폰은 없거나 하나. 코드 직접 사용 쿠폰은 userCoupons 발급 문서 없이 사용될 수 있으며, 자동 발급 쿠폰은 보유 여부를 확인합니다.
최신 쿠폰 조건과 기존 주문 금액은 따로 보관합니다.

userCoupons에는 발급 당시 조건 사본이 있지만, 쿠폰 목록·적용 시에는 coupons의 최신 조건을 우선 확인합니다. 접수된 주문의 discountAmount와 totalAmountNumber는 확정값으로 유지됩니다. couponUses는 상태 문서이므로 전체 감사 이력을 대신하지 않습니다.

접근 범위주요 데이터
공개 읽기상품, 카테고리, 공개 재고, 공개 설정, 리뷰, 공개 문의. 수정은 관리자·작성자 등 별도 규칙 적용
본인 / 관리자주문·주문 이벤트와 비밀 문의는 해당 회원 또는 관리자만 직접 조회. 비회원 주문은 복구 정보를 확인하는 서버 함수로 조회
본인 전용 직접 조회users 프로필과 userCoupons. 관리자 가입자 화면의 계정·쿠폰 정보는 권한 검사를 거친 서버 함수에서 제공
관리자 직접 조회비공개 재고·재고 이력, 쿠폰 행사, 관리자 승인 설정, 구형 게시물과 방문 통계
서버 전용 쓰기주문·주문 이벤트·재고·공개 재고·쿠폰 발급/사용 및 보조 기록. 브라우저의 임의 쓰기는 차단

Firestore·Storage 보안 규칙은 클라이언트 접근을 제어합니다. Cloud Functions의 Admin SDK는 서버 코드에서 별도로 권한을 검사합니다. App Check는 사이트 키 설정 시 초기화되는 선택 기능이며, 현재 주문의 필수 조건은 아닙니다.

브라우저에 남는 데이터

장바구니·찜, 주문 재시도와 비회원 조회용 정보, 팝업 숨김 설정 일부는 해당 브라우저에 저장됩니다. 브라우저 데이터를 지우거나 기기를 바꾸면 그대로 이어지지 않을 수 있습니다.

회원 프로필·주문·쿠폰은 서버 데이터입니다. PWA는 오프라인 안내 페이지만 캐시하며 주문 데이터베이스를 오프라인 복제하지 않습니다.

운영자가 직접 하는 일

실제 은행 입금 대조, 계좌 환불, 반품 검수와 택배 인계는 운영자의 업무입니다. 시스템은 처리 결과와 재고 변동을 기록합니다.

백업·보관기간·알림 수집 등 외부 운영 설정은 이 구조도만으로 활성화 여부를 확인할 수 없습니다.

검토 근거: functions/index.js·commerce.js·couponWallet.js·couponGrants.js·members.js, firestore.rules, storage.rules 및 현재 상품·회원·설정 화면 코드. 데이터 구조를 설명하기 위한 문서로 실제 운영 데이터나 인증키를 포함하지 않습니다.
